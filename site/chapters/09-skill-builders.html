Chapter 9 · Explore

Meet the people building skills

Four well-known skill authors, what they made, and what the rest of us can borrow.

Read this first

They write for programmers. Why look?

  • All four collections below are made for AI coding assistants. You won't use most of them directly.
  • But their ideas are the best examples of good skill design anywhere: short, focused, and each one does one job.
  • Several of their skills (interviewing, explaining, rewriting, researching) work for any job. Next page onward shows which.

Star counts and skill lists below were read from GitHub on 29 Oct 2026. They change often.

Builder 1

poteto · "pstack"

GitHub display name "lauren poteto". Software engineer; the bio lists the React Compiler core team and xAI. The pstack page says they have worked on large codebases at Meta, Netflix and Cursor.

What it is

A set of skills, "playbooks" and short principles that make an AI coding assistant behave like a careful engineering team. Published on Cursor's plugins repo; a mirror works with Claude Code, Codex and Cursor. MIT license.

The philosophy

  • "If you want to go fast, go deep first."
  • Less code of higher quality, not more.
  • The best spec is the work itself, so no heavy planning by default.

Example skills: /how explains a system /why finds reasons behind it /interrogate tries to break your work /unslop removes AI-style writing tells /reflect saves a long task's recipe

One entry skill, /poteto-mode, picks from 23 playbooks. Sources: GitHub profile · pstack mirror (3.1k stars)

Builder 2

Matt Pocock · "Skills for Real Engineers"

TypeScript educator. Repo tagline: "Straight from my .agents directory." About 306k stars.

The idea

Small, easy-to-adapt, composable skills, built against four problems: the AI misunderstanding you, wordiness, broken work, and a tangled mess over time.

Standouts for everyone

  • grill-me: interviews you about a plan until the open questions are settled
  • teach: teaches a concept over several sessions
  • research: investigates a question and saves cited findings
  • handoff: summarizes a chat so someone else can continue
  • wait-what: re-explains a message that didn't land

github.com/mattpocock/skills (MIT license). Install help is in its README. Coding skills in it include tdd, diagnosing-bugs and code-review.

Builder 3

Jesse Vincent · "Superpowers"

Built with the team at Prime Radiant. Blog: blog.fsck.com. About 308k stars.

A full working method, packaged as skills: brainstorm → plan → do → review → finish.

brainstorming

Clarify what you want and make a design before any work starts.

writing-plans

Break the work into small, checkable tasks.

verification-before-completion

Check the work really works before saying it's done.

github.com/obra/superpowers (MIT license). It also includes a writing-skills skill that teaches the AI to write new skills.

Builder 4

Addy Osmani · "agent-skills"

Created the project with collaborators. About 112k stars.

25 skills organized like a project's life: Define, Plan, Build, Verify, Review, Ship.

Worth borrowing

  • interview-me: asks you questions to clarify a vague request
  • idea-refine: sharpens a rough idea
  • documentation-and-adrs: records decisions and why

Nice design touch

Each skill has steps, verification gates and a checklist, so the AI has to prove each stage is done before moving on.

github.com/addyosmani/agent-skills (MIT license)

What good skill authors share

Five habits

  1. Small and focused. One skill, one job.
  2. Ask first, act second. Interview before building.
  3. Prove it. Verification steps before "done".
  4. Shared vocabulary. Pocock's skills keep a glossary so the AI uses your words.
  5. Composable. Skills call each other, like Lego.
